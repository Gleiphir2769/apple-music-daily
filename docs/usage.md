# 每日音乐发现 · 整合版

退出旧版，再打开 MusicKitProbe.app。默认界面不再展示历史验证页。

## 首次连接

点击“账户连接与授权”：
- 音乐资料库：在此点击授权，调用本机 MusicAuthorization。
- ChatGPT 与 Apple Music：在下方网页登录并连接 Apple Music，登录／授权由用户完成。
- 完成后点击“完成连接，返回推荐”。

## 日常使用

选择最近歌曲数量或添加日期范围，点击“一键推荐”。这会读取资料库、生成提示词、填入 ChatGPT 并自动点击一次发送；无需复制粘贴。首次使用按钮下方有数据发送说明。

等待时覆盖对话界面，保留同一个 WKWebView 的布局和会话。检测到本次请求被网页收录、停止生成、唯一的新 Apple Music iframe 后，只展示该实时 iframe。保留宿主和 iframe 的通信，不复制其内容，不提取登录凭据，也不代点添加歌曲或创建歌单。

卡片通过 iframe 标题、来源域名或附近的明确 Apple Music 标题识别。网页结构变化、卡片未展开、插件未连接、发送需确认等情况可能导致自动识别失败。可点“显示网页处理登录或确认”；“更多”也提供完整网页、仅显示卡片、系统浏览器、手动请求和诊断导出。无法唯一定位时不猜测卡片或按钮。

存在手动草稿或其他回复生成时不会覆盖或发送；一次任务最多点击一次发送，失败不自动重发。停止等待只取消本地工作，已发送的 ChatGPT 请求可能继续运行。重新点击“一键推荐”是用户主动开始新的请求。

资料库日期筛选包含首尾日期，以本机时区为准，最多扫描 10000 首，最多选取500首；扫描截断和缺失时间会提示。导入与预览移到“更多 → 查看请求与导入”。“发送当前预览”使用导入或已生成样本，“一键推荐”重新读取实时资料库。

## 验证范围

Swift 编译及签名通过；JavaScript 语法通过。Mock DOM 测试覆盖已有草稿保护、修改后草稿保护、禁用发送按钮、最多一次发送、旧卡片排除、无关 iframe 排除和消息确认。此前实际50首资料库导出已验证可生成请求。

本次自动发送、自动展开与仅卡片布局尚未在用户已登录的实时 ChatGPT 页面完成验证。未申请电脑控制权限。发生问题可通过“更多 → 保存诊断”导出状态、iframe 标题与域名；不包含 Cookie、令牌或对话正文。

在仓库根目录构建：bash scripts/build.sh；产物：build/MusicKitProbe.app（macOS 14+，Apple Silicon，已安装 Xcode）。

## 输入适配修复（v2）

填入后等待编辑器更新并重新获取 DOM 节点，连续两次确认完整文本；同时读取富文本段落结构以避免 innerText 换行差异。只有完全空输入框才尝试粘贴事件备用方式，部分插入或用户编辑不会被覆盖。发送前仍校验全文，最多点击一次发送。诊断包含预期/实际字符数量及首个差异位置，不含输入正文。

新增 Mock DOM 回归测试覆盖段落、异步节点替换、空插入备用、部分插入拒绝、实际文本变化拒绝。真实 ChatGPT 页面需运行确认。

## 自动草稿重试（v3）

若请求已完整填入但尚未点击发送，再次主动点击“一键推荐”可替换同一页面中应用留下且内容未变的自动草稿。手动草稿、部分填入的请求、被修改的草稿、页面跳转后的草稿，以及已点击发送但结果未知的请求，仍需在网页处理，不会自动覆盖或重发。重启后的旧草稿无法确认来源，需发送或复制保存后清空。

Mock DOM 回归测试覆盖以上重试和保护路径；真实登录页面仍需验证。

## 新对话与思考强度

每次开始推荐或打开“账户连接与授权”都会重新载入 ChatGPT 的新对话入口，保留登录状态。

点击顶部“推荐设置”会展示 ChatGPT 网页和设置说明。在网页中手动调整思考强度滑块，建议选择中，也可按需选择；完成后点击“完成设置，返回推荐”。新对话沿用网页保存的设置，应用不再自动操作思考控件，也不会因为无法识别思考强度而阻止发送。

“推荐设置”和“显示完整网页”保留当前会话；开始推荐时才重新打开新对话。网页自动化仍需在实际登录页面验证。

## 请求输入（v6）

富文本输入优先使用纯文本粘贴事件，让网页编辑器处理完整文本，避免模拟键入可能触发的智能引号替换。仅在输入框仍为空时才使用模拟键入备用方式；部分填入或内容发生变化仍会停止发送。校验失败诊断增加首个差异字符的 Unicode 编码，不包含请求正文。

已用 Mock DOM 覆盖粘贴、部分粘贴保护和智能引号差异；实际网页效果需运行验证。


### 完整推荐表格

新版一键推荐要求 ChatGPT 在生成 Apple Music 歌单卡片后输出结构化的 10 首歌曲明细。结果页上方展示歌曲、艺人、已核实的专辑名及完整推荐理由，可滚动查看；下方保留一份原始 Apple Music 卡片用于试听和保存。表格只读取本次请求对应的新回复，不会拿旧歌单补齐缺失数据。

旧会话没有结构化明细时，会显示提取提示，可以查看原始回复，或点击“再推荐一次”生成新版结果。若回复仍在补充，可以点击“重新提取”。“显示完整网页”会恢复网页布局，顶部“返回推荐”可切回结果页。


推荐生成时，Apple Music 卡片可能先于 JSON 明细出现。应用会先显示可用卡片，并继续自动读取完整歌曲理由，直到本轮等待结束；不需要切换到原始网页再返回。卡片出现后的等待可以单独停止，已有卡片会保留；稍后也可点击“重新提取”。
